# 6.2.1 智能手表数据上传功能测试

## a. 测试对象

微信小程序"智能随访"中的智能手表健康数据上传功能（蓝牙采集 + HTTP 同步至六元服务器数据库）。

## b. 测试目的

验证测试者佩戴的智能手表与小程序蓝牙连接后，手表采集的**心率、血氧、步数**三项健康数据能正确通过小程序上传至六元服务器 MySQL 数据库 `smart_followup_research` 对应表中。

## c. 测试设备

- 待测软件：微信小程序"智能随访"（已部署到测试环境）
- 智能手表：Veepoo 智能手表（型号 R04 戒指 或 VP-W680，已充电、佩戴可正常采集数据）
- 测试手机：安装最新版微信、蓝牙开启、定位权限开启
- 中转服务：本地 Node.js 服务（`scripts/health-data-server.js`，端口 3000，已启动）
- 后端数据库：六元服务器 MySQL（库名 `smart_followup_research`）
- 数据库验证工具：能连接六元服务器 MySQL 的客户端（如 Navicat 或 `mysql` 命令行）

## d. 测试步骤

### ① 准备

1. 测试人员在六元服务器 MySQL 客户端记录**测试前**三张表的最大主键作为基线：

   ```sql
   SELECT MAX(id) AS hr_max  FROM vital_heart_rate;
   SELECT MAX(id) AS spo2_max FROM vital_blood_oxygen;
   SELECT MAX(id) AS step_max FROM vital_signs WHERE data_type = 'steps';
   ```

   记录这三个数值，后续步骤用于对比验证新增数据。

2. 测试者将智能手表佩戴在手腕（或手指，戒指型号），确认手表已开机并正常显示。

### ② 蓝牙连接

3. 在测试手机上打开微信，进入"智能随访"小程序首页，看到顶部标题"智能随访"、副标题"健康监测 · 数据自动同步"。

4. 确认首页中央状态卡片显示"未连接设备 / 请连接您的智能手表"。

5. 点击首页中央按钮 **"🔍 连接智能手表"**，进入"蓝牙连接"页。

6. 页面顶部状态栏依次显示"扫描中…"、"搜索中… 第 1 轮"，下方设备列表会陆续出现附近的蓝牙设备，每条显示"设备名 / 信号强度 / MAC 地址"。

7. 在列表中找到测试手表（设备名形如 `VPR04-xxxx` 或 `VP-W680-xxxx`），**点击该列表项**。

8. 状态文字变为"正在连接..."，等待 5–12 秒完成握手。

9. 连接成功后页面自动返回首页，状态卡片由灰变绿，显示"设备名 / 电量 X% / 今日 X 步"，底部出现"数据自动同步中"动画指示。

> 若 12 秒内出现错误弹窗，点击弹窗中的 **"重试"** 按钮重试一次；仍失败则点击 **"返回扫描"** 重新选择设备。

### ③ 数据采集与上传

10. 保持手表佩戴状态，让测试者**静坐 1–2 分钟**，期间手表会自动采集心率与血氧；同时**起身走动 30 步以上**，让步数计数发生变化。

11. 小程序在收到手表数据后会**自动**通过 POST 请求上传到本地服务（端口 3000），本地服务再转发写入六元服务器数据库，全过程无需手工操作。

12. 在小程序首页观察状态卡片中的"今日 X 步"数值随走动而增加，说明数据已经从手表流入小程序。

### ④ 在六元服务器数据库中验证（关键步骤）

13. 切回 MySQL 客户端，连接六元服务器，执行以下查询，确认三类数据均已新增（`id` 应大于步骤 1 记录的基线，`recorded_at` 应在本次测试时间窗内）：

    a) **心率**：

    ```sql
    SELECT id, patient_id, device_id, heart_rate, recorded_at
    FROM vital_heart_rate
    ORDER BY id DESC
    LIMIT 5;
    ```

    b) **血氧**：

    ```sql
    SELECT id, patient_id, device_id, spo2, recorded_at
    FROM vital_blood_oxygen
    ORDER BY id DESC
    LIMIT 5;
    ```

    c) **步数**（存于通用表 `vital_signs`，`data_type = 'steps'`）：

    ```sql
    SELECT id, patient_id, device_id, data_type, vital_data, recorded_at
    FROM vital_signs
    WHERE data_type = 'steps'
    ORDER BY id DESC
    LIMIT 5;
    ```

14. 三条查询返回的最大 `id` 均**大于**步骤 1 记录的基线，且 `recorded_at` 落在本次测试时段内，即视为数据成功上传至六元服务器。

### ⑤ 结束

15. 回到小程序首页，点击 **"✕ 断开连接"** 按钮断开蓝牙。

16. 测试人员保留 MySQL 查询结果截图与小程序首页截图作为存档证据。

## e. 验收判定

若步骤 9（连接成功）、步骤 12（步数实时增长）、步骤 14（六元数据库三张表均查到本次时间窗内的新行）全部满足，判定本功能测试**通过**。任一步骤未满足则记录失败现象（错误弹窗截图、数据库无新行、设备未连接等）并提交开发组分析。
