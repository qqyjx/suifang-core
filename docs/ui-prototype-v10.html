智能随访 v10 — 原型设计稿

配套: prototype/index.html 是可点击 HTML 原型, 本文是文字版设计规格 (供 Pencil/Excalidraw 类工具画图用 + 后续小程序实施输入)

设计目标: 把 v10 的"25+ 按钮单页宫格"重构为"4-tab 医疗专业架构", 信息层级清晰, 患者中心化导航

实施方案 (设计稿 → 小程序)

阶段 1: 框架搭建 (~1 天)

  • app.json 加 tabBar 配置 4 个 tab + 图标资源
  • 新建 4 个页面: pages/home/, pages/measure/, pages/data/, pages/settings/
  • 旧 pages/index/ 内容拆解到 pages/home/, 旧 page 文件不删 (跳转复用)

阶段 2: Tab 1 首页 (~1 天)

  • patient-card / conn-card 复用现有 v10 less
  • 快速采集 4 大按钮 (新组件)
  • 今日统计 (调 server 拉数据 + 本地缓存)
  • 最近测量列表 (本地 storage 取近 5 条)

阶段 3: Tab 2 测量 (~0.5 天)

  • 三个 list-group 渲染 12 项, 每项跳转到现有 page (复用现成的体征采集页面)

阶段 4: Tab 3 数据 (~2 天)

  • 患者 chip 切换 (调 /api/data?patientNo=xxx)
  • ECharts / F2 集成 (微信小程序版本)
  • 异常数据规则 (血压 ≥ 140/90 算异常等)
  • 导出 CSV 功能

阶段 5: Tab 4 我的 (~0.5 天)

  • list-group 渲染各项, 大部分点击跳转现有 page
  • 调试入口 wx:if="{{isTestBuild}}" 控制显隐

阶段 6: 测试 + 上线 (~0.5 天)

  • BUILD_TAG → 5.06-v10
  • 真机回归测试
  • 微信开发者工具上传 5.6.10 选为体验版

总工时估算: ~5 天 (1 人), 不含图标设计 (建议用 emoji 兜底, 或 IconFont 替换)

风险与折中

  1. 现有 25+ 个 page 的代码不动 — 仅做导航重组, 风险极低
  2. 服务端 0 改动 — 现有 /api/data?patientNo=xxx 已支持 Tab 3 所需查询
  3. 数据通道 0 改动 — Tab 2 的"测量"跳现有 page, 数据采集逻辑完全保留 v9
  4. 图表库 — 微信小程序里 ECharts 集成有点麻烦, 备选: F2 (蚂蚁出品, 小程序原生支持) 或自己 canvas 画
  5. 回退 — 任何阶段觉得不好用, 把旧 pages/index/ 设为启动页即可秒回退到 v10

给客户/医生看原型的方式

  1. WSL/Windows 起 server: 
    cd prototype && python3 -m http.server 8080
  2. 电脑浏览器: http://localhost:8080/
  3. 真机扫码: 手机和电脑同 WiFi → http://<电脑IP>:8080/
  4. iOS 长按地址栏 → "添加到主屏幕" → 伪装成 App 体验
