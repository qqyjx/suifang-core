一、与 S101 的根本区别 已确认

维度S101 (Veepoo)iwown 4G
联网BLE 蓝牙（无 4G）自带 4G 蜂窝
数据桥微信小程序无桥，手表直连
协议Veepoo 私有 BLE二进制 protobuf + 自定义帧（HTTP）
客户端重（57 页小程序）零（厂商固件）
服务端收 JSON :3000收二进制 :8099
指向我们小程序配 URL域名烧录（蓝牙 APK 改址）

一句话：S101 端上桥接，iwown 云端直收。

二、数据链路 已确认

iwown 手表 ──4G POST 二进制──→ dc.ncrc.org.cn/iwown/ ──反代──→ 192.168.4.104:8099 ──→ 六元 MySQL
  (前15字节 device_id        (六元 nginx 加 location)    (iwown_server.py)     (iwown_data 表)
   + 多个 0x4454 帧)          处理完返回单字节 0x00
与 S101 共用同一台服务器 + 反代 + 六元 MySQL，iwown 独立进程/端口 + 新 /iwown/ location + 新表，互不影响。

三、二进制帧格式 已确认（app.py 实证）

body = device_id(15 字节 ASCII) + 帧1 + 帧2 + ... (多帧拼接, 小端)

每帧:
  prefix   uint8[2]   固定 0x44 0x54 ("DT")
  length   uint16     payload 长度 (小端)
  crc      uint16     payload CRC (见下)
  opt      uint16     协议编码 (小端): 0x80 / 0x0A / 0x12
  payload  uint8[len] protobuf 序列化内容

读到末尾无多余字节即结束。处理成功返回单字节 0x00 (0x02 长度不足 / 0x03 帧头错)
CRC 待确认: 官方 Flask 示例 提取 crc 字段但未校验，算法（多项式/初值）文档未明给。我方服务当前与示例一致 不校验 CRC（先收数据），需要时向 iwown 要算法。
Content-Type 坑（已规避）: 手表上报 Content-Type 写 x-www-form-urlencoded 但实为二进制。我方用 Python 原生读原始字节流， 不做表单解析，无需 nginx 改写 Content-Type（Spring Boot 才需要）。

五、opt → protobuf 与体征字段 已确认（proto + 示例）

opt顶层 message含义
0x80HisNotification → HisDataHealth分钟级历史健康（也含 ecg/rri/spo2/3rd-party 等子类型）
0x0AOM0Report实时：电量/信号/步数距离卡路里/GNSS 定位（最近5条）
0x12Alarm_infokConfirm报警：心率/血氧/跌倒/SOS-GNSS/血压/久坐/血糖…

0x80 健康单条含（HisDataHealth，均为当分钟值）

字段内容换算
pedo_data步数/距离/卡路里距离、卡路里 ÷10
hr_data心率 min/max/avg—
bxoy_data血氧 min/max/avg—
bp_data血压 sbp/dbp—
hrv_datafatigue 疲劳压力 = 100 − fatigue
temperature_data体温（esti_arm/evi_body 各打包2值）高/低 16 位 ÷100
另有 sleep / af 房颤 / mdt / bioz 体成分 / blood_sugar / mood / breath … 共 23 个可选子字段
时间戳 DateTime.seconds（fixed64，Unix 秒；data.rst 注明按 UTC 表示）。我方入库 decoded_json 用 MessageToDict 全量保留，抽常用体征做索引列，raw_hex 兜底可重算。

七、我方接收服务（已建） server/

移植官方 Flask 示例为 stdlib http.server（无 Flask 依赖，风格对齐 S101 health_server.py）：

  • iwown_server.py — 6 端点 + 建表 + 入库 + 落盘兜底（不丢数据三重保障） + /api/status + /api/iwown/list
  • iwown_parser.py — 解帧 + 按 opt 解 protobuf（MessageToDict 无损）。解帧逻辑已合成帧自测：device_id/多帧/0x02/0x03/降级 全绿
  • theproto/ 38 个 _pb2.py · schema.sql · iwown.service · nginx-iwown.conf · deploy-iwown.ps1

入库表 iwown_data

一行一帧：device_id + data_type + opt + recorded_at + 抽取体征列（hr/spo2/bp/温度/压力/步数…）+ decoded_json（全量）+ raw_hex（兜底）。另 iwown_device 存 device→患者绑定。
